## Findings to address before RFQ integration

1. **Preserve page evidence and flag pages without text.**
   `tools/pdf_text/lib/pdf_text.rb:74-82` discards empty page text and returns
   a flattened string plus total page count. A mixed text/scanned RFQ can lose
   content without warning. Return numbered page text and explicit extraction
   warnings before relying on this for quote readiness. Never silently skip a
   damaged or unreadable page and declare the RFQ complete.
2. **Handle file-access errors in the CLI.**
   `tools/pdf_text/bin/pdf-to-text:13-16` catches extraction errors but not a
   missing/unreadable path. A missing-file invocation reproduces a raw stack
   trace. Catch file-system failures and add a focused CLI regression test.
3. **Bound file reads before allocation.**
   The CLI reads the entire file before the library's 100 MB check. Use a bounded
   read or intake size enforcement before accepting untrusted uploads. The text
   limit also runs after extraction, so it is not a parser resource limit.
4. **Define the shared result and readiness rules.**
   The app needs values, units, source locations, catalog candidates, benchmark
   metadata, compliance evidence, unresolved fields, and draft questions. A
   probability score alone must not turn missing required evidence into Ready.
5. **Review research examples before turning them into expected outputs.**
   The open-web report's "Same item, different words" section includes a
   14-gauge 60-by-120 example alongside 16-gauge 48-by-96 examples. The file
   acknowledges the different size, but its introductory equivalence claim is
   inaccurate. Keep these as distinct cases, not equivalent normalization pairs.
